# Design: Recipe Actions, Product Sale Watchlist & App Rating Prompt

**Date:** 2026-05-31  
**Status:** Draft; Feature 1 implemented

---

## Context

Three user-facing improvements requested after feedback:

1. **Recipe Actions** — the saved recipe detail sheet is currently read-only. Users need to delete, export to a shopping list, edit, and share saved recipes from within that sheet.

2. **Product Sale Watchlist** — users want to flag products and be alerted when they go on sale. Implemented as an in-app banner check (no push backend required), with a clear hook for future push notifications.

3. **App Rating Prompt** — nudge satisfied users to rate the app on the Play Store / App Store using the native in-app review sheet.

---

## Feature 1: Recipe Actions

**Implementation status:** Complete as of 2026-06-07.

Implemented:

- Sticky saved-recipe action bar with Delete, Save to List, Edit, and Share actions.
- `RecipeEditSheet` for editing recipe name, servings, and instructions.
- Delete and edit persist to Supabase through the existing recipe repository.
- Save to List reuses the export preparation sheet and exports the saved recipe passed into the sheet.
- Share uses `share_plus` to open the native share sheet with plain-text recipe content.

Implementation notes:

- `share_plus` was added to `pubspec.yaml` and `pubspec.lock`.
- `showExportPreparationSheet()` now uses direct recipe export so saved recipes do not depend on the recipe generation provider's current state.
- Flutter generated plugin registrants were refreshed by `flutter pub get` for `share_plus`.

Future task:

- Add ingredient editing to `RecipeEditSheet`: allow add/remove/reorder/edit ingredient rows, update `Recipe_Ingredients` directly, and clear stale product match fields when ingredient text or quantity changes so export does not keep an incorrect product match.

### What changes

The existing `_showRecipeDetailSheet()` in `recipe_screen.dart` gains a **sticky action bar** pinned to the bottom of the sheet. The four actions are:

| Action | Icon | Behaviour |
|--------|------|-----------|
| Delete | `delete_outline` | Confirmation dialog → `deleteRecipe()` → dismiss sheet + remove from list |
| Save to List | `playlist_add` | Opens `showExportPreparationSheet()` (existing export flow, reused exactly) |
| Edit | `edit_outlined` | Opens a new `RecipeEditSheet` (separate bottom sheet) |
| Share | `share_outlined` | Formats recipe as plain text → `Share.share()` via `share_plus` package |

The swipe-to-dismiss delete on the card is kept as-is (already works). Delete in the sheet is an additional entry point.

### Recipe Edit Sheet (`RecipeEditSheet`)

A `showModalBottomSheet` with three editable fields:

- **Name** — `TextFormField`, required, max 100 chars
- **Servings** — number stepper (same `+`/`-` pattern as `add_to_list_sheet.dart`)
- **Instructions** — `TextFormField` with `maxLines: null` (multi-line), one instruction per line

On save: calls `repository.saveRecipe(recipe.copyWith(...))` (upsert by `recipeId`). Updates the `savedRecipesProvider` list in-place via `ref.invalidate()`.

### Share format

Plain text assembled as:

```
{recipeName}

Ingredients:
• {formattedQuantity} {ingredientName}
...

Instructions:
1. {step}
...

Generated by Milk
```

Uses `share_plus` (`Share.share(text)`). No new backend required.

### Save to List (from recipe detail sheet)

Reuses `showExportPreparationSheet()` from the recipe flow and passes the saved `Recipe` object. Implementation required a small export-flow fix so saved recipes export the passed recipe instead of relying on the recipe generation provider's current state.

### Files touched

- `lib/presentation/screens/recipes/recipe_screen.dart` — add action bar to `_showRecipeDetailSheet()`, wire up delete + share + edit + save-to-list
- `lib/presentation/widgets/recipes/recipe_edit_sheet.dart` — new file for `RecipeEditSheet`
- `lib/presentation/widgets/recipes/export_preparation_sheet.dart` — export the saved recipe passed into the sheet

## Feature 2: Product Sale Watchlist

### Data model

New Supabase table: **`product_watchlist`**

| Column | Type | Notes |
|--------|------|-------|
| `id` | `uuid` PK | auto |
| `user_id` | `uuid` FK → `auth.users` | RLS: user owns row |
| `product_index` | `text` | Matches `LiveProduct.productIndex` / `Product.index` |
| `product_name` | `text` | Display name at time of flagging |
| `retailer` | `text` | Store name |
| `price_when_flagged` | `numeric` | Regular price at flag time |
| `created_at` | `timestamptz` | auto |

RLS policy: `user_id = auth.uid()` on all operations.

### Flutter data layer

**Model:** `WatchedProduct` — mirrors table columns + computed `isOnSale(LiveProduct current)` helper.

**Repository:** `WatchlistRepository`
- `watchProduct(LiveProduct)` / `watchProduct(Product)` — insert row
- `unwatchProduct(productIndex)` — delete row  
- `getWatchlist()` → `List<WatchedProduct>`
- `isWatched(productIndex)` → `bool`

**Provider:** `watchlistProvider` — `AsyncNotifier<List<WatchedProduct>>`, exposes `watch()` / `unwatch()` methods that optimistically update state.

### Watch button placement

A **bookmark/bell icon button** added to:

1. `LiveProductDetailScreen` — top-right of the app bar
2. `ProductDetailScreen` (legacy) — same position
3. Product cards (live product cards) — small icon in the top-right corner of the card, toggled filled/outlined

Tapping toggles watched state. Shows a `SnackBar`: "Watching {name} for sales" / "Removed from watchlist".

### Sale detection (in-app, on refresh)

**Triggered:** When the user opens the Products tab (not on every app startup — avoids unnecessary API calls on cold launch).

**Rate limit:** Capped at 10 products checked per session. If the watchlist exceeds 10 items, check the 10 most recently added. This keeps API usage predictable.

A `WatchlistSaleChecker` utility (called from the Products tab's `initState` / `ref.listen`):

1. Fetches the user's watchlist (`getWatchlist()`)
2. Takes the most recent 10 entries
3. For each, calls `liveApiServiceProvider.searchProducts(productName, retailer: retailer)` with `limit: 1`
4. If the top result has `hasPromo == true`, it's flagged as on sale

Results stored in a `saleAlertsProvider` (`Map<String, bool>` keyed by `productIndex`).

### In-app alert UI

If `saleAlertsProvider` has any hits when the user opens the app or the Products tab:

- A **dismissible banner card** appears at the top of the Products screen listing "X items on your watchlist are on sale!" with a "View" button
- "View" opens a `WatchlistSheet` — a bottom sheet listing watched products, with sale badges on those currently on sale
- Each item in the sheet has an "Add to List" button (calls `showAddToListSheet()`) and an "Unwatch" button

### Files touched

- `supabase/migrations/` — new migration for `product_watchlist` table + RLS
- `lib/data/models/watched_product.dart` — new model
- `lib/data/repositories/watchlist_repository.dart` — new repository
- `lib/presentation/providers/watchlist_provider.dart` — new provider + sale checker
- `lib/presentation/screens/products/live_product_detail_screen.dart` — add watch button
- `lib/presentation/screens/products/product_detail_screen.dart` — add watch button
- `lib/presentation/widgets/products/live_product_card.dart` — add watch icon
- `lib/presentation/widgets/products/watchlist_sheet.dart` — new bottom sheet
- `lib/presentation/screens/products/` (home/products tab) — add sale alert banner

## Feature 3: App Rating Prompt

### Trigger

After the user **saves a recipe for the 3rd time** (cumulative, not per-session). This is a high-satisfaction moment — the user has just completed a meaningful action and has enough app history to give a meaningful rating.

The count is tracked in `shared_preferences` under key `recipe_save_count`. The prompt fires once when the count crosses 3, and never again (tracked by a `has_prompted_for_review` flag in `shared_preferences`).

### Mechanism

Uses the [`in_app_review`](https://pub.dev/packages/in_app_review) package:

```dart
final inAppReview = InAppReview.instance;
if (await inAppReview.isAvailable()) {
  await inAppReview.requestReview();
}
```

The OS controls whether the sheet actually appears (Google Play / App Store enforce their own rate-limiting — typically once per ~30 days per user). No custom dialog needed.

### Where it's called

In `recipe_provider.dart`'s `saveRecipe()` method, after a successful save:
1. Increment `recipe_save_count` in `shared_preferences`
2. If count == 3 and `has_prompted_for_review` is false → call `requestReview()` → set flag to true

### Files touched

- `pubspec.yaml` — add `in_app_review` dependency
- `lib/presentation/providers/recipe_provider.dart` — increment count + trigger review after save
- `lib/data/services/review_service.dart` — new thin wrapper around `in_app_review` (keeps provider testable)

## Verification

### Recipe Actions
1. Open Saved Recipes tab → tap a recipe → verify action bar is visible with 4 buttons
2. **Delete**: tap delete → confirm dialog → recipe disappears from list
3. **Save to List**: tap → export preparation sheet opens with ingredients pre-populated
4. **Edit**: tap → edit sheet opens → change name/servings/instructions → save → sheet closes, card reflects new values
5. **Share**: tap → system share sheet opens with formatted text including name, ingredients, instructions

### Product Watchlist
1. Open a product detail screen → tap watch icon → snackbar confirms → icon turns filled
2. Tap again → snackbar confirms removal → icon turns outlined
3. Kill and relaunch app → watched product still appears in watchlist (persisted to Supabase)
4. If a watched product has a promo: open Products tab → sale alert banner appears
5. Tap "View" on banner → watchlist sheet opens → on-sale items show sale badge
6. Tap "Add to List" on a sale item → `showAddToListSheet()` opens correctly

### App Rating Prompt
1. Save a recipe 3 times → on the 3rd save the native in-app review sheet appears
2. Dismiss and relaunch → saving more recipes does NOT trigger the sheet again
3. Share text does not contain emoji — ends with "Generated by Milk"
